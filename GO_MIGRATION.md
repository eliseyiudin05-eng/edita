# Поэтапная миграция KIVRONIX на Go

Текущий production-сайт продолжает работать на Next.js и Supabase. Go вводится параллельно, поэтому ни один этап не требует остановки сайта.

## Версионирование

- Каждый подготовленный нами исходный коммит получает ровно один следующий patch-тег: `v1.0.2`, `v1.0.3` и далее.
- Версия в `package.json` и Go build metadata совпадает с тегом без префикса `v`.
- Служебный workflow больше не пушит дополнительные коммиты: deployment bundle хранится как CI-артефакт.
- Тег создаётся только после успешных проверок и указывает на проверенный исходный коммит.

## Стратегия без простоя

1. **v1.0.2 — фундамент (готово).** Изолированный Go HTTP-сервис, безопасные настройки, health/readiness, контейнер и CI. Трафик остаётся в Next.js.
2. **v1.0.3 — инфраструктура данных (готово).** Подключение Go к Supabase/PostgreSQL, проверка JWT/JWKS, общий формат ошибок и аудит запросов. Только диагностический доступ.
3. **v1.0.4 — первый read-only API (готово).** Безопасное чтение настроек обучения профиля: Go проверяет JWT и читает только строку владельца под пользовательской RLS. Next.js сравнивает ответы старого и нового API после отправки ответа, но пользователю всегда отвечает старый API. Теневой режим выключен по умолчанию.
4. **v1.0.5 — canary (готово).** Отдельный флаг направляет 1–10% чтений настроек обучения в Go. Ошибка, тайм-аут, некорректный ответ или превышение лимита задержки переключают текущий запрос на старый Supabase-путь. При 20% ошибок в окне 10–20 результатов circuit breaker останавливает canary на пять минут; несовпадение контракта останавливает его сразу. Canary выключен по умолчанию.
5. **v1.0.6 — обучение, чтение прогресса (готово).** Go получает отдельный read-only контракт с завершёнными уроками и рассчитанным XP. Браузер читает прогресс через Next.js gateway, а Go сверяется с прежним ответом только после отправки ответа пользователю. Теневой режим выключен по умолчанию; запись прогресса и начисление XP не переносились.
6. **v1.0.7 — canary прогресса обучения (готово).** Отдельный флаг направляет 1–10% чтений прогресса в Go. Ошибка, тайм-аут, некорректный ответ или превышение лимита задержки возвращают текущий запрос на прежний Supabase-путь. Circuit breaker приостанавливает canary на пять минут при деградации или сразу после несовпадения контракта. Canary выключен по умолчанию.
7. **v1.0.8 — социальный рейтинг, чтение (готово).** Go получает отдельный read-only контракт для 50 публичных профилей рейтинга. Браузер больше не обращается к `public_profiles` напрямую: ответ выдаёт авторизованный Next.js gateway, а Go сверяется в фоне и не влияет на пользователя. UUID профилей и непубличные поля из нового контракта исключены.
8. **v1.0.9 — canary социального рейтинга (готово).** Отдельный флаг направляет 1–10% чтений рейтинга в Go. Ошибка, тайм-аут, некорректный ответ или превышение лимита задержки возвращают текущий запрос на прежний Supabase-путь. Circuit breaker приостанавливает canary на пять минут при деградации или сразу после несовпадения контракта. Canary выключен по умолчанию.
9. **v1.0.10 — список друзей, чтение (готово).** Go получает read-only контракт только для отношений подтверждённого пользователя. RLS разрешает чтение строки исключительно её участникам, UUID участников удаляются из ответа, а фоновой shadow не влияет на пользователя. Поиск, отправка, принятие и отмена запросов остаются в Next.js/Supabase.
10. **v1.0.11 — canary списка друзей (готово).** Отдельный флаг направляет 1–10% чтений списка друзей в Go. Ошибка, тайм-аут, некорректный ответ или превышение лимита задержки возвращают текущий запрос на прежний путь. Circuit breaker приостанавливает canary на пять минут при деградации или сразу после несовпадения контракта. Canary выключен по умолчанию.
11. **v1.0.12+ — остальные домены по одному.** Группы, компании, чаты и AI переносятся отдельными версиями. Финансовые операции и escrow мигрируют последними.
12. **Финальный этап.** TypeScript остаётся фронтендом и тонким gateway; бизнес-логика и защищённые операции выполняются Go-сервисом.

## Условия переключения каждого маршрута

- контрактные и интеграционные тесты проходят;
- Supabase RLS и серверные проверки прав не ослаблены;
- старый обработчик остаётся доступен для мгновенного отката;
- метрики ошибок и задержек сравниваются до canary;
- повторные финансовые запросы идемпотентны;
- секреты хранятся только в переменных окружения платформы.

## Включение и откат canary v1.0.5

1. Сначала включить теневое сравнение и убедиться, что ответы совпадают.
2. Установить HTTPS origin Go-сервиса в `GO_BACKEND_URL`, выключить теневой режим, затем задать `GO_BACKEND_CANARY_READS_ENABLED=true` и `GO_BACKEND_CANARY_PERCENT=1`. Активный canary сам подавляет теневые запросы, чтобы не удваивать нагрузку на Go.
3. Проверять события `go_profile_canary` и `go_profile_canary_compare`; они не содержат токены, идентификаторы или значения профиля.
4. Повышать долю не более чем до 10 только после стабильного окна. Для глобального мгновенного отката установить `GO_BACKEND_CANARY_READS_ENABLED=false`; автоматический локальный откат выполняет circuit breaker.

## Теневое чтение обучения v1.0.6

- `GO_BACKEND_ACADEMY_SHADOW_READS_ENABLED=false` сохраняет старый путь единственным источником ответа.
- После развёртывания Go-сервиса флаг можно включить для фонового сравнения `GET /v1/academy/progress` с Next.js/Supabase.
- Событие `go_academy_shadow` содержит только маршрут, результат сравнения и длительность — без токена, пользователя, списка уроков и XP.
- Ошибка, тайм-аут, слишком большой или несовпадающий ответ Go не влияет на пользователя. Canary для этого домена появится только после стабильных теневых результатов.

## Ограниченный canary обучения v1.0.7

1. После стабильных теневых сравнений выключить `GO_BACKEND_ACADEMY_SHADOW_READS_ENABLED` и включить `GO_BACKEND_ACADEMY_CANARY_READS_ENABLED=true`.
2. Начать с `GO_BACKEND_ACADEMY_CANARY_PERCENT=1`; значение жёстко ограничено диапазоном до 10%.
3. Проверять события `go_academy_canary` и `go_academy_canary_compare`; они не содержат токены, пользователей, список уроков или XP.
4. Ошибка, медленный или некорректный ответ Go возвращает тот же запрос на legacy. При 20% нездоровых результатов в окне 10–20 запросов circuit breaker отключает локальный canary на пять минут; несовпадение контракта открывает его сразу.
5. Для глобального отката установить `GO_BACKEND_ACADEMY_CANARY_READS_ENABLED=false`. Записи прогресса и начисление XP остаются в Next.js/Supabase.

## Теневое чтение социального рейтинга v1.0.8

- `GO_BACKEND_SOCIAL_SHADOW_READS_ENABLED=false` сохраняет прежний Next.js/Supabase-путь единственным источником ответа.
- После развёртывания Go-сервиса флаг можно включить для фонового сравнения `GET /v1/social/ranking` после отправки legacy-ответа пользователю.
- Оба пути используют пользовательский access token и publishable key, поэтому политика чтения `public_profiles` остаётся активной; service-role key в Go не передаётся.
- Контракт ограничен 50 строками и только публичными полями. Внешний ответ не содержит UUID, email, возраст, доход, onboarding или иные настройки профиля.
- Событие `go_social_shadow` содержит только маршрут, результат сравнения и длительность. Ошибка, тайм-аут, большой, некорректный или несовпадающий ответ Go не влияет на пользователя.

## Ограниченный canary социального рейтинга v1.0.9

1. После стабильных теневых сравнений выключить `GO_BACKEND_SOCIAL_SHADOW_READS_ENABLED` и включить `GO_BACKEND_SOCIAL_CANARY_READS_ENABLED=true`.
2. Начать с `GO_BACKEND_SOCIAL_CANARY_PERCENT=1`; значение жёстко ограничено диапазоном до 10%.
3. Проверять события `go_social_canary` и `go_social_canary_compare`; они не содержат токены, UUID, имена, usernames, школы, аватары, навыки или баллы.
4. Ошибка, медленный или некорректный ответ Go возвращает тот же запрос на legacy. При 20% нездоровых результатов в окне 10–20 запросов circuit breaker отключает локальный canary на пять минут; несовпадение контракта открывает его сразу.
5. Для глобального отката установить `GO_BACKEND_SOCIAL_CANARY_READS_ENABLED=false`. Все социальные записи остаются в Next.js/Supabase.

## Теневое чтение списка друзей v1.0.10

- `GO_BACKEND_SOCIAL_FRIENDS_SHADOW_READS_ENABLED=false` сохраняет текущий Next.js/Supabase-путь единственным источником ответа.
- После применения миграции RLS и развёртывания Go флаг включает фоновое сравнение `GET /v1/social/friends`; тайм-аут ограничен диапазоном 250–3000 мс.
- Go фильтрует отношения по проверенному JWT subject и повторно проверяет каждого участника ответа. Пользовательский токен и publishable key сохраняют participant-only RLS.
- Контракт ограничен 200 отношениями. UUID участников не возвращаются; остаётся только ID отношения, необходимый для принятия или отмены запроса, и публичная карточка второго участника.
- Событие `go_social_friends_shadow` содержит только маршрут, исход сравнения и длительность. Список друзей, имена, username, аватары, школы, токены и идентификаторы не журналируются.
- Поиск друзей и все изменения отношений продолжают выполняться существующим серверным маршрутом. После стабильных теневых сравнений доступен отдельный canary `v1.0.11`.
