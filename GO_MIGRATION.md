# Поэтапная миграция KIVRONIX на Go

Текущий production-сайт продолжает работать на Next.js и Supabase. Go вводится параллельно, поэтому ни один этап не требует остановки сайта.

## Версионирование

- Каждый подготовленный нами исходный коммит получает ровно один следующий patch-тег: `v1.0.2`, `v1.0.3` и далее.
- Версия в `package.json` и Go build metadata совпадает с тегом без префикса `v`.
- Служебный workflow больше не пушит дополнительные коммиты: deployment bundle хранится как CI-артефакт.
- Тег создаётся только после успешных проверок и указывает на проверенный исходный коммит.

## Стратегия без простоя

1. **v1.0.2 — фундамент (готово).** Изолированный Go HTTP-сервис, безопасные настройки, health/readiness, контейнер и CI. Трафик остаётся в Next.js.
2. **v1.0.3 — инфраструктура данных (готово).** Подключение Go к Supabase/PostgreSQL, проверка JWT/JWKS, общий формат ошибок и аудит запросов. Только диагностический доступ.
3. **v1.0.4 — первый read-only API (готово).** Безопасное чтение настроек обучения профиля: Go проверяет JWT и читает только строку владельца под пользовательской RLS. Next.js сравнивает ответы старого и нового API после отправки ответа, но пользователю всегда отвечает старый API. Теневой режим выключен по умолчанию.
4. **v1.0.5 — canary (готово).** Отдельный флаг направляет 1–10% чтений настроек обучения в Go. Ошибка, тайм-аут, некорректный ответ или превышение лимита задержки переключают текущий запрос на старый Supabase-путь. При 20% ошибок в окне 10–20 результатов circuit breaker останавливает canary на пять минут; несовпадение контракта останавливает его сразу. Canary выключен по умолчанию.
5. **v1.0.6 — обучение, чтение прогресса (готово).** Go получает отдельный read-only контракт с завершёнными уроками и рассчитанным XP. Браузер читает прогресс через Next.js gateway, а Go сверяется с прежним ответом только после отправки ответа пользователю. Теневой режим выключен по умолчанию; запись прогресса и начисление XP не переносились.
6. **v1.0.7 — canary прогресса обучения (готово).** Отдельный флаг направляет 1–10% чтений прогресса в Go. ## Условия переключения каждого маршрута

- контрактные и интеграционные тесты проходят;
- Supabase RLS и серверные проверки прав не ослаблены;
- старый обработчик остаётся доступен для мгновенного отката;
- метрики ошибок и задержек сравниваются до canary;
- повторные финансовые запросы идемпотентны;
- секреты хранятся только в переменных окружения платформы.

## Включение и откат canary v1.0.5

1. Сначала включить теневое сравнение и убедиться, что ответы совпадают.
2. Установить HTTPS origin Go-сервиса в `GO_BACKEND_URL`, выключить теневой режим, затем задать `GO_BACKEND_CANARY_READS_ENABLED=true` и `GO_BACKEND_CANARY_PERCENT=1`. Активный canary сам подавляет теневые запросы, чтобы не удваивать нагрузку на Go.
3. Проверять события `go_profile_canary` и `go_profile_canary_compare`; они не содержат токены, идентификаторы или значения профиля.
4. Повышать долю не более чем до 10 только после стабильного окна. Для глобального мгновенного отката установить `GO_BACKEND_CANARY_READS_ENABLED=false`; автоматический локальный откат выполняет circuit breaker.
